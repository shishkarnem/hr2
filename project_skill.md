# Project Skill: Робот Рекрутер (RR) — AI Recruitment & Training Platform

Руководство и архитектурный свод правил для разработчиков и ИИ-агентов по сопровождению, модификации и развитию платформы **«Робот Рекрутер (RR)»**.

---

## 1. Архитектура и стек технологий

1. **Модель исполнения (Full-Stack в едином процессе)**:
   - **Фронтенд**: React (TypeScript, Vite, Tailwind CSS).
   - **Бэкенд**: Express в `server.ts` с модульными контроллерами и роутами (`server/routes/`).
   - **Режимы запуска**:
     - **Dev**: `npm run dev` запускает `tsx server.ts`.
     - **Production**: `npm run build && npm start` (сборка фронтенда Vite и компиляция бэкенда через esbuild в `dist/server.cjs`).
   - **Сетевая конфигурация**: сервер слушает порт `process.env.PORT || 3000` на адресе `0.0.0.0`.

2. **База данных — Cloud PostgreSQL («hr» на ProTalk)**:
   - **Единый источник истины**: облачная реляционная база данных **PostgreSQL («hr»)**, размещенная на защищенной инфраструктуре ProTalk.
   - **Методы взаимодействия**:
     - **HTTP Proxy API**: `https://db.pro-talk.ru/api/proxy/query` с авторизационным заголовком `X-User-Id`.
     - **Протокол MCP**: `https://db.pro-talk.ru/api/databases/hr/mcp` (Model Context Protocol JSON-RPC 2.0).
   - **Клиент доступа (`server/pgClient.ts`)**:
     - Обеспечивает выполнение параметризованных SQL-запросов (`$1, $2, ...`), валидацию типов и автоприведение JSON-структур в нативный PostgreSQL `JSONB`.
     - Поддерживает автоматический повтор запросов при сетевых микросбоях и защитный таймаут 10 секунд.
     - Асинхронно реплицирует операции записи (`INSERT`, `UPDATE`, `DELETE`) в облачную базу данных.
   - **Серверные триггеры PostgreSQL**:
     - На всех ключевых таблицах (`projects`, `companies`, `employers`, `candidates`, `training_blocks`, `interview_blocks`, `wallets`) установлены триггеры `BEFORE UPDATE`, автоматически актуализирующие временные метки `updated_at = NOW()`.
   - **Облачные Cron-задачи**:
     - Ежедневное автоматическое резервное копирование базы данных в 06:00 МСК (`0 3 * * *` UTC) со снимком состояния и отправкой отчета в Telegram.
     - Регулярная очистка устаревших временных записей и лимитов.

3. **Облачное хранилище файлов (ProTalk Storage)**:
   - Все бинарные файлы (логотипы, аватары, регламенты, резюме, видео, аудио) загружаются в **ProTalk Storage** (`https://file.pro-talk.ru/tgf/`) с постоянными CDN-ссылками.
   - В базе данных сохраняются исключительно полученные прямые URL (никаких бинарников в БД).
   - Публичные ЧПУ-ссылки вида `/files/:id/:filename` и `/file/:id` выполняют быстрый HTTP 302-редирект с браузерными заголовками кэширования (`Cache-Control: public, max-age=604800`). На сервере не хранится дисковый кэш, что исключает рассинхронизацию при замене файлов в базе данных.

## 2. Нейросетевое ядро (ИИ) и ProTalk API

### 2.1. Единый источник истины: Таблицы `protalk_bots` и `protalk_prompts`
- **Отсутствие хардкода**: токены ботов (`bot_token`), идентификаторы ботов (`bot_id`), системные промпты (`system_prompt`), префиксы чатов (`user_prefix`), температура (`temperature`) и конечные точки API всегда запрашиваются из облачных таблиц `protalk_bots` и `protalk_prompts`.
- В базе данных зафиксированы промпты для всех функциональных задач:
  - Базовые промпты для стандартного рабочего бота `66337`.
  - Усиленные ProMax-промпты с суффиксом `_promax` для экспертного бота повышенной точности `bot_id = 67370`.

### 2.2. Резервный режим «Повторить с RR ProMax»
- Во всех оверлеях генерации и экранных сообщениях об ошибках предусмотрена возможность повторного вызова **«Повторить с RR ProMax»**.
- При активации запрос направляется к боту `67370` с использованием соответствующего промпта `<promptKey>_promax`.

### 2.3. Сквозное логирование всех вызовов ИИ в таблицу `logs`
Каждое обращение к нейросети фиксируется в таблице `logs` через единый механизм `saveAILog` со следующими параметрами:
- `channel_id`: идентификатор сессии чата (например, `{employer_id}_RRcompany`, `demo{id}_RRsituations`).
- `user_social_id`: цифровой ID пользователя.
- `user_message`: входной текст запроса или входные данные.
- `bot_reply`: полученный ответ модели.
- `channel_name`: имя системного промпта (`prompt_key`), соответствующее задаче.
- `bot_id`: идентификатор бота (`66337`, `67370` и др.).
- `llm`: алиас модели (`hr_rr`, `promax`, `function_369`, `stt_from_widget`).
- `tokens_in_source`, `tokens_out_source`, `tokens_total`: объем входящих, исходящих и суммарных токенов.
- `cost_rub`: расчетная стоимость запроса в рублях (формула: `tokens_total * 0.00003` руб).
- `tokens_used_usd`: эквивалент в долларах США (`cost_rub / 95`).
- `function_error`: текст ошибки при неудачном вызове или `null`.
- `created_at`: точная метка времени запроса.

## 4. Свод правил верстки и дизайн-системы (Apple Liquid Glass)

При создании, рефакторинге и оформлении любых компонентов, экранов и диалоговых окон строго соблюдаются следующие правила:

### 4.1. Фон и контейнеры (Liquid Glass)
- **Запрет цветных подложек**: в стандартной теме запрещено использовать затемнение или осветление фона какими-либо цветами в контейнерах.
- **Разрешенные варианты фона**:
  - Полностью прозрачный фон (`bg-transparent`).
  - Размытие фона (`backdrop-blur-md`, `backdrop-blur-xl`, `backdrop-blur-2xl`) с ультра-тонким эффектом матового стекла (`bg-white/[0.03]`, `bg-black/[0.15]`).
- Допускаются мягкие золотистые блики (`rgba(231,199,104,0.05)`).

### 4.2. Цветовая палитра и запрещенные цвета
- **Строгий запрет зеленого и красного**: категорически запрещено использовать зеленый (`green-*`, `emerald-*`, `lime-*`) и красный (`red-*`, `rose-*`) в контейнерах, блоках, кнопках или текстах.
  - Для статусов успеха, активности и подтверждения: золотой акцент (`#E7C768`, `#C9A84C`), белый цвет или янтарный (`amber-*`).
  - Для предупреждений и ошибок: приглушенный золотисто-охристый, нейтральный стеклянный или янтарный оттенок.
- **Цвета текста**:
  - Золотой градиент для акцентов и главных заголовков: `bg-gradient-to-r from-[#E7C768] to-[#C9A84C] bg-clip-text text-transparent`.
  - Белый / полупрозрачный белый для информационного текста: `text-white`, `text-white/90`, `text-white/70`.
- **Границы**:
  - Золотой контур или градиент: `border border-[#E7C768]/30 hover:border-[#E7C768]/60`.
  - Тонкая грань матового стекла: `border border-white/10 hover:border-white/20`.

### 4.3. Типографика и регистр
- **Минимальный размер шрифта**: во всем приложении минимальный размер шрифта составляет **14px (`text-sm`)**. Текст меньше 14px (10px, 11px, 12px, 13px) строго запрещен.
- **Запрет капслока**: **никогда не использовать капслок (UPPERCASE)** в интерфейсе. Классы `uppercase` запрещены для кнопок, меню, табов, заголовков и плашек. Весь текст оформляется в естественном регистре предложений.

### 4.4. Эталон модальных окон
- Эталоном стиля, цветов, отступов, радиуса скругления (`rounded-3xl` / `rounded-2xl`) и фонового размытия является окно **ИИ-ассистента** (`src/components/EmployerAIAssistant.tsx`). Все модальные окна в приложении выравниваются по этому эталону.

### 4.5. Тема из базы данных компании
- Для страниц конкретной компании (`/company/:slug`, `/vacancy/:slug`) и связанных с ними модальных окон обязательно учитываются стилевые параметры из базы данных (`companies.theme_config`, цвета, шрифты, логотип).
- При обнаружении несоответствий в верстке контейнеров параметры автоматически приводятся к утвержденному стилю.

### 4.6. Мобильная адаптивность
- **Табы без горизонтальной прокрутки**: в мобильной версии горизонтальная прокрутка табов заменяется на:
  - Вертикальные стеки кнопок в стиле Liquid Glass.
  - Выпадающие списки (dropdown) с кнопками в фирменном стиле.
- **Ширина и перенос строк**: соблюдать корректную ширину компонентов (`w-full`, `max-w-full`, `break-words`). Никакие плашки или строки не должны вызывать появление горизонтального скролла на мобильных устройствах.

### 4.7. Стандарты рефакторинга кода
- В каждом файле с исходным кодом должно быть **не более 1000 строк**.
- Код разделяется по тематическим папкам и подпапкам.
- В одной папке размещается **не более 5 файлов**.
